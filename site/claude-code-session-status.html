Under the hood

How Steerify knows what a Claude Code session is doing

Hooks, never the terminal output. And one look at the transcript, to tell "finished" from "asked you something".

The question that sits in scrollback for 40 minutes, while you think Claude is still working. That one.

The short answer

Every Claude Code session that Steerify starts carries a few Claude Code hooks. Each hook event flips the session's state in the app: working, idle, or needs you. When a session stops, Steerify reads Claude's last reply in the session transcript to see whether it is done or waiting on an answer. The terminal you see is a real terminal, and Steerify never reads what is printed in it.

1. Hooks, added per session

Steerify starts each session with claude --settings and a small hook file of its own. Your settings files are not edited, and your own hooks keep running next to these:

  • SessionStart, SessionEnd
  • UserPromptSubmit, PreToolUse, PostToolUse
  • Stop, StopFailure
  • Notification, PermissionRequest

The hook is a few lines of shell. It writes the name of the last event, and the time, to one small status file per session.

2. From event to state

Hook eventWhat you see
A prompt, or any tool useWorking. Claude is rowing.
StopIdle. Then the transcript decides what kind of idle (see below).
A permission request, or a notificationNeeds you. The tab is marked, and the menu bar shows a count.
Session endEnded.

The app watches the status folder with macOS file events (FSEvents). There is no polling: nothing runs while nothing happens.

3. Finished, or asked you something?

A Stop event only says Claude stopped typing. It does not say why. So when a session goes idle, Steerify reads Claude's last reply from the session transcript (the .jsonl file Claude Code keeps for every conversation) and sorts it:

  • A question that is not on the board shows as "asks you: …". The session stays open.
  • A next step Claude would take shows as "next: …", with a Go on button.
  • Work that waits on the board (a test, a choice, a release) counts as done. The board has it, so the chat no longer needs you.
  • Nothing left counts as done.

This is plain reading of a local file. No model is called and no tokens are spent.

4. Why not read the terminal?

  • It breaks. Claude Code's screen is a text interface that changes between versions. A scraper has to be fixed every time it does.
  • It polls. To notice a change on screen you have to keep looking at the screen. With 99 sessions, that is 99 loops.
  • It guesses. Hooks are Claude Code telling you what happened. Screen text is you guessing.

Questions

Does it change my Claude Code setup?

No. The hook file is passed per session. Sessions you start yourself, outside Steerify, are untouched.

Where is the status kept?

In Steerify's own folder under Application Support on your Mac. One tiny file per session, replaced on every event. Nothing leaves your machine.

What does Steerify do with the state?

It shows it on every session tab and roadmap item, counts what needs you in the menu bar, and ⌘J jumps to the next thing waiting on you.

Can I read the code?

Yes, it is open source. Look at Status.swift and SessionOutlook.swift in the repository.
